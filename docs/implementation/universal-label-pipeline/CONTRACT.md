# Frozen universal pipeline contract (T01)

Design frozen for T02–T11; not implemented. Approved requirements D01–D13 in [DECISIONS](DECISIONS.md) remain authoritative. Technical defaults below can change only with recorded rationale, updated dependent tests/docs and review; accepted requirement changes require NEEDS_REPLAN.

## Intake and canonical JSON

Exactly one universal URL: POST `/api/v1/label-intake`, application/json UTF-8. No version field, aliases, facts envelope or SAP-specific routing. Fixture `/labels/process` and `/simulation/fixture` remain separate. No Data Tokens mutation, import-triggered printing or browser dataset selection change.

```json
{"sender":{"system":"EXTERNAL_DEMO"},"request_id":"REQ-001","mode":"simulation","field_descriptions":{"ZZWIDTH":"Width"},"items":[{"item_id":"I1","label_code":"ROLL_DEMO","copies":2,"data":{"ZZWIDTH":695,"ZZCHARG":"BATCH-001","ZERO":0,"FLAG":false,"EMPTY":"","NULL":null}}]}
```

Reject unknown members at envelope/sender/item levels, duplicate JSON member names at any level, malformed JSON, NaN/Infinity, booleans/string/fractional copies, unsupported modes and schema versions. All shown envelope/item members required except field_descriptions; descriptions default to empty metadata only. sender has only system. Identifiers system/request_id/item_id: 1..128 ASCII `[A-Za-z0-9][A-Za-z0-9_.:-]*`; label_code: 1..128 `[A-Za-z0-9][A-Za-z0-9_-]*`. No trimming/case conversion; item_id unique within ordered items, 1..100 entries. data is an object, 0..200 entries; values string/finite JSON number/boolean/null only. Numbers restricted to safe integer range when integral; fractional values must survive shared browser/server conversion parity tests. Keys 1..128 `[A-Za-z0-9_-]+`, excluding `__proto__`, `constructor`, `prototype`. Descriptions use same keys, up to 200 entries/string values 0..256 Unicode characters. String data <=4096 Unicode characters, UTF-8 <=16384 bytes per value. Preserve exact strings/keys/item order; field descriptions never enter barcode or text substitution. Object member ordering is preserved for exploration; it is not business semantics in digest identity.

Historical canonical samples missing mode remain read-only local exploration with a visible missing-mode warning and output disabled until the user selects a mode in a new working copy. Saving a new canonical dataset requires strict mode/copies validation. Existing copies=1000 is invalid for canonical output, with explicit correction required. Do not rewrite stored operational records. v1.1/raw-v2 stay separate local exploration parsers and cannot reach intake without an explicit user-created canonical envelope.

Numeric profile is finite IEEE-754 binary64. Reject integral absolute values >9007199254740991; fractional values parse once to binary64, then use ECMAScript JSON.stringify number serialization (shortest roundtrip digits, its exponent thresholds/signs, -0 serializes to 0). Python must implement this exact profile, not str(float); shared golden cases in P05 are mandatory. Digest uses the same numeric spelling, sorted object keys by UTF-16 code units, compact separators, JSON escaping and no Unicode normalization (JCS-compatible numeric/string profile). Numbers are semantic JSON numbers, not preserved source lexical formatting; send formatted decimals/leading-zero business identifiers as strings.

## Draft contract and media authority

Keep POST `/api/v1/simulation/editor-preview` and `/api/v1/printing/editor`; replace composed-SVG-only input at T06, without compatibility fallback. Each request contains required `draft:{svg,width_mm,height_mm,dpi,binding_version:1}`, required `data:{...}`, optional `field_descriptions:{...}`, required `encoder:"IPL"`, required `copies:1..999`. Print additionally accepts optional existing `target:{host,port}`; simulation rejects target. There is no intake sender/request_id/mode envelope on editor routes: route defines sink; UI print is a deliberate action. Editor draft may be unsaved; no external approval gate is imposed on manual Studio output.

```json
{"draft":{"svg":"<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"40mm\" height=\"30mm\" viewBox=\"0 0 160 120\"><rect x=\"0\" y=\"0\" width=\"160\" height=\"120\" fill=\"white\"/></svg>","width_mm":40,"height_mm":30,"dpi":203,"binding_version":1},"data":{},"encoder":"IPL","copies":1}
```

Server validates finite media 10..500 mm, 72..600 DPI and exact root mm width/height plus viewBox origin 0,0 at 4 editor units/mm; mismatches reject, no client pixel override. Stored intake uses immutable stored version media/checksum and the same validator/binder/font/rounding/cutoff=128/edge policy/codec. Template logical coordinates are 4 units/mm; output dots are round(mm*dpi/25.4). Shared editor edge normalization may pad a white one-dot edge only; larger mismatches fail. Equal inputs include media, font file digest, renderer version, binding version/options, language and copies. PNG compressed bytes need not match when decoded raster pixels match; IPL bytes must match exactly.

## Binding v1 feature subset

SVG root carries `data-binding-version="1"` for canonical templates; draft binding_version must agree. Plain static templates may omit root metadata only if no dynamic metadata is present; admission attaches v1 without changing authored pixels. Unknown versions, conflicting field/placeholder, nested dynamic owners or undeclared/unknown data-* binding metadata reject. Legacy metadata is explicitly migrated in T03 editor working copies; intake never infers missing options from sample images.

Canonical dynamic text uses `data-field` with exact key or `data-payload-spec` base64 UTF-8 JSON `{version:1,template:"literal {{KEY}}"}`; aliases data-placeholder must equal data-field. Template grammar only literals and `{{KEY}}` with optional surrounding whitespace. No braces outside complete tokens, eval, arbitrary code, nested lookup, formatting expressions or description interpolation. Required references: absent -> missing_binding; null -> null_binding; empty string -> empty_binding. 0 becomes "0", false becomes "false"; numbers use shared tested locale-independent JSON numeric spelling. XML text escaping occurs once. Literal static empty text is allowed. Bound text <=4096 characters, line count <=100. Text/tspan preserve explicit style/line layout; binder deterministically rebuilds multiline tspans from authored line metrics (no browser wrapping guesses); dynamic rich per-character styling/wrapped textbox requiring unavailable metrics fails unsupported_feature until parity proven.

Support static rect/line/circle/ellipse/polygon/polyline/path, text/tspan, nested g, affine translate/rotate/scale/skew/matrix and finite geometry. Preserve group transforms and authored colors. Static embedded PNG/JPEG/WebP images are bounded and decoded before render; no file/network href. Support bounded local gradients/clipPath definitions/references after validation; reject missing/cyclic references, filter/mask, external assets, use, scripts/events, animation, foreignObject, declarations/entities, arbitrary stylesheet/import and unsupported elements/attributes. Inline style is restricted to known presentation properties. T03 must create a complete explicit allowlist from actual Fabric fixtures, not treat svg_safety as proof. Unhandled current Studio features require NEEDS_REPLAN before cutover.

Dynamic barcode/QR nodes have one canonical owner g with payload source (one field or composition), symbology, geometry/transform and complete base64 JSON `data-symbol-spec` `{version:1,type,options}`. Bound image sample/value is not authority. Type only code128/code39/ean13/qrcode; no fallback. Linear options required: module_width (positive finite editor units), bar_height, margin=2, display_value=false, font_size=12, checksum policy (Code39 false, EAN13 verified). Options beyond frozen subset reject. QR options required: ecc L/M/Q/H, margin=1, size positive finite, encoding profile `utf8`, segmentation `byte`, version auto or integer 1..40, mask auto or integer 0..7. Persist chosen effective version/mask in prepared evidence. All symbols regenerate black on white before authored geometry transform. Code128 printable ASCII <=512 chars; Code39 `[0-9A-Z $%+\-./]+` <=512; EAN13 exactly 13 digits with valid check digit; QR nonempty UTF-8 <=2048 bytes and capacity validated. Defaults applied only by explicit editor metadata creation, never inferred for existing dynamic images. Human-readable text enabled/nondefault margins/options are rejected pending separately proven support.

## Finite budgets and scheduling

| Resource | Frozen limit and admission behavior |
| --- | --- |
| HTTP body | 2 MiB UTF-8, streamed count before parsing; 413 request_too_large |
| Templates | 512 KiB UTF-8 each, <=10000 XML nodes, nesting <=32, dynamic owners <=200, path commands <=100000 |
| Images | <=1 MiB total decoded compressed image bytes/template and <=4 million decoded pixels total; each image <=4096/side; reject before resvg |
| Output | <=4096 dots/side and <=4 million pixels/item; aggregate <=16 million pixels/batch; sum copies <=9990 |
| Preparation | Sequential; one in-flight request/process, no queue; excess admission 429 intake_busy; resvg 15 seconds/item, preparation wall deadline 60 seconds/batch |
| Prepared retention | Sum encoded IPL <=16 MiB and PNG <=8 MiB/batch; <=2 MiB IPL and <=1 MiB PNG/item; total working reservation 128 MiB/request; reserve before prepare, enforce actual size before send |
| Response | <=12 MiB including base64 inline PNG and JSON; results <=100, error message <=256 chars; reserve worst-case PNG expansion +64 KiB result metadata before print |
| Print | Existing connect 3 seconds/send 10 seconds, sequential one attempt/item; transport phase <=1300 seconds for 100 items, no preparation deadline interruption after claim |

All aggregate media/copies bounds checked before raster. Prepare ALL print items and build bounded results before any send; aggregate actual-size/deadline/binding/policy failure prevents all sends. Simulation retains ordered failures and continues within remaining budgets; a batch deadline/budget prevents subsequent work with SKIPPED. Enforce memory reservation at admission and process limits as well as sizes; violation is failure, not truncation. No response resource allocation may introduce a new reject after printing begins.

## Response and error mappings

Successful processing response HTTP 200 even for item failures: required request_id (external identity), trace_id (current server UUID), original_trace_id (initial admission UUID), mode, replayed boolean, status (batch status), summary:{total,simulated,submitted,failed,uncertain,skipped}, ordered results. Each result requires item_index (zero-based), item_id,label_code,copies,status,template (null before resolution else {version,svg_sha256}), error (null or {stage,code,message}), confirmed:false for SUBMITTED/UNCERTAIN. SIMULATED additionally contains simulation:{png_base64,width_px,height_px,dpi,payload_sha256,payload_bytes}; print never exposes raw bytes or raw business input. Failed/skipped items contain no PNG. batch status is COMPLETED if all succeed, PARTIAL if mixed, FAILED if none succeed, UNCERTAIN if any uncertain (precedence over other outcomes); no accepted-only success.

Result status SIMULATED / SUBMITTED / FAILED / UNCERTAIN / SKIPPED. Stages ADMISSION/RESOLUTION/BINDING/PREPARATION/POLICY/CLAIM/TRANSPORT/RECOVERY. Bounded codes: unknown_label_code, layout_unavailable, invalid_template, unsupported_feature, missing_binding, null_binding, empty_binding, invalid_binding, invalid_symbol, invalid_media, raster_failed, codec_failed, resource_limit, preparation_timeout, template_not_approved, target_not_allowed, preflight_aborted, transport_failed_before_send, submission_uncertain, previous_uncertain, batch_stopped, processing_failed. Messages are static public vocabulary <=256 characters, never exception/raw-data text. FAILED means provably no submission for that item; UNCERTAIN means possible send. Print preflight offenders FAILED and other items SKIPPED/preflight_aborted; transport uncertainty stops later items SKIPPED/batch_stopped. Proven pre-send transport failure also stops later batch items, requiring deliberate new request after inspection.

Pre-processing error shape `{request_id:null-or-validated-id,trace_id,detail:{stage:"ADMISSION",code,message}}`: 400 malformed_json/duplicate_member; 401 unauthenticated; 403 sender_not_allowed/mode_not_allowed; 413 request_too_large; 415 unsupported_media_type; 422 invalid_request/invalid_mode/invalid_copies; 409 request_conflict/request_in_progress/request_expired; 429 intake_busy; 503 ledger_unavailable/policy_unavailable/intake_unavailable. HTTP 500 processing_failed only for failure before durable admission; after any transport claim return durable per-item UNCERTAIN or a correlated 503 response_unavailable whose client semantics are uncertain, never retry permission. No 404 batch rejection: unknown label is an item resolution failure.

## Identity, durable replay and security

Authenticated server sender identity + exact external request_id is unique; sender.system is an asserted name verified against credential mapping, never credentials itself. Choose per-sender bearer secrets loaded from ignored environment/config, constant-time verification, TLS termination required for shared network deployment; no token in JSON/logs. Policy configuration explicitly authorizes simulation/print and label codes. Missing auth/policy denies external intake; current local Studio remains its existing local trust boundary, not new shared-deployment readiness.

Digest canonical JSON with recursively sorted object keys, UTF-8, exact strings/array order, finite canonical numbers; include descriptions/mode/copies and all accepted request values. Same identity/digest terminal replay returns retained outcomes with replayed=true and original pins, never sends. Different digest ->409. Admission atomically records digest, pinned immutable templates/media/checksums, selected policy revision/target identifiers and ordered items before processing. Duplicate concurrent request ->409 request_in_progress, no second worker. Revalidate current source authorization before disclosing retained results; revocation may deny replay access. Pinned approvals/target identity must still be valid immediately before first claim; policy changes during sending stop subsequent claims, never reroute/rebind silently.

Durable item states RECEIVED -> PREPARED -> SEND_CLAIMED -> SUBMITTED or UNCERTAIN; simulation PREPARED -> SIMULATED; failures before SEND_CLAIMED ->FAILED, remaining ->SKIPPED. Persist claim and payload digest/copies/target revision BEFORE socket construction. Failure committing claim ->no send. Crash at/after claim, failed terminal commit, lost acknowledgement or ambiguous socket send ->UNCERTAIN; startup recovery never auto-sends claimed items and skips later items. Before-claim crash may safely mark failed/skipped for explicit replay response; no background automatic resumption. Never derive receipt from job-foundation state. Reconciliation is separately authorized human review, append-only evidence; new request_id only after deliberate decision, no automatic retry endpoint.

Raw input exists only transiently in memory; no raw data in ledger/logs. Persist keyed HMAC request digest, pins, status/errors, timestamps, target ID/policy revision and payload digest; no payload/PNG for print. Simulation PNG responses kept in protected durable result storage 24 hours, then replay ->409 request_expired without recomputation. Print bounded terminal metadata retained 90 days; permanent minimal tombstones (sender identity, keyed digest/request identity HMAC, timestamps/outcome) prevent reuse after expiry; expired keys ->409. Secret HMAC keys versioned/retained for tombstone comparison; rotation cannot permit resend. Retention cleanup/schema migrations are later authorized operations. No falsely finite claim: tombstone volume is monitored and admission denies before capacity exhaustion; local quota technical default 1 million identities/database, 503 ledger_unavailable once reached, never evict to permit reuse.

## T02 implemented admission clarification

Copies uses semantic integral JSON values (1,1.0,1e0 equivalent); typed models normalize to int. Raw JSON nesting limit32 and strict UTF8/BOM/duplicate member rejection are implemented. Object admission uses the common compact-JSON string/punctuation reservation with32 bytes per number, bounded at2MiB in addition to raw bytes. This reversible resource refinement prevents Python/JS float-serialization size drift. Missing-mode historical copies1..1000 is read-only; explicit working-copy corrections are required, never a silent output clamp. ECMAScript binding number rendering and JCS digest remain T04/T08, with required golden evidence before their consumption; T02 does not claim those output/digest gates.
